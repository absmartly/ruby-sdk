## [2.0.0] - Unreleased

Behavior now matches the JavaScript SDK (the reference implementation). Each Breaking entry says who is affected.

### Breaking
- After `close`, `experiments`, `set_override` and `set_overrides` no longer raise "ABSmartly Context is closed"; the other read methods still raise it, as in v1.3.0. Before the context is ready, `publish` and `refresh` now raise "ABSmartly Context is not yet ready". Affects code that relied on those raising (or not raising).
- `close` and `refresh` return `nil` (or, for `refresh`, the failure) instead of an Array. Affects code that used their return values.
- `close` and `finalize` after a failed final publish raise the publish error and leave the context open with its events queued, so the caller finds out and can retry: a second `close` republishes and seals, and the `"close"` (or `"finalize"`) event is logged only once the context is sealed. A routine collector rejection (e.g. HTTP 5xx) raises a `PublishError`, a `StandardError`, so it is catchable with an ordinary `rescue`. v1.3.0 sealed the context and orphaned the events. Affects code that called `close` without handling a raised publish error.
- A failed `refresh` no longer marks the context failed: it logs the error, returns it and keeps the current data. `refresh` on a failed context is a no-op.
- The `publish` event is logged only once a publish succeeds; a failed publish logs an `error` event instead. Affects event loggers that counted `publish` events.
- `create_context` no longer raises connection errors such as `Faraday::ConnectionFailed`: the context is returned failed (`failed?` is true) and the error goes to the event logger. `rescue Faraday::ConnectionFailed` around `create_context` no longer triggers.
- A context fetch whose body can't be deserialized now fails the context instead of leaving it never ready.
- Shared variable keys: when several experiments define the same variable, `variable_value` and `peek_variable_value` read from the first experiment, in experiment id order, that the unit is assigned to or overridden in, exposing each experiment visited on the way (as the JavaScript SDK does). v1.3.0 always read and exposed the last experiment in the payload. `variable_keys` likewise now maps a shared key to the experiment with the lowest id instead of the last one in the payload. Affects units in more than one experiment sharing a variable key.
- Numeric audience comparisons follow the JavaScript SDK's number coercion. Affects strict-audience users with numeric attributes, which may move to or from control.
- An audience is re-evaluated after `set_attribute`/`set_attributes` (through the `attrs_seq` counter), as in the JavaScript SDK: when newly supplied attributes flip the audience result, the cached assignment is recomputed, so a unit can move and an extra exposure is sent. v1.3.0 kept the assignment made before the attributes were set. Affects code that set attributes after a treatment or variable read.
- An invalid regex in a `match` audience now sets `audienceMismatch`, so strict audiences assign control. `match` no longer caps pattern/text length.
- Float unit UIDs are hashed from JavaScript's `toFixed(0)` text (e.g. `1.5` as `"2"`), so units with Float UIDs are reassigned. Integer, BigDecimal and Rational UIDs hash as in v1.3.0.
- Strings in non-UTF-8 encodings (e.g. UTF-16) are transcoded to UTF-8 before hashing, so those units are reassigned; surrogate pairs written as CESU-8 are joined and lone surrogates or invalid bytes become U+FFFD. UTF-8 strings are unaffected.
- `track` raises `ArgumentError` for properties that are neither a Hash nor respond to `to_h` (e.g. a String or Array). `ActionController::Parameters` (through `to_unsafe_h`, so unpermitted params are accepted as in v1.3.0) and other `to_h` objects are converted.
- `DefaultContextEventHandler` is a deprecated alias of `DefaultContextPublisher`, so its `.name` is `"DefaultContextPublisher"`. `ContextEventHandler` is likewise an alias of `ContextPublisher`.
- `Array.wrap`, `String#underscore` and `String#compare_to` core extensions removed.

### Changed
- When `publish` sends a switchback exposure in a request of its own (see Added), the event logger receives one `publish` event per request delivered (a failed request logs an `error` event instead and stops the call), so a single `publish` call can log more than one. Payloads without switchbacks still send at most one request, and none when nothing is queued.
- `set_attribute` stores a copy of a String, Array or Hash value (nested to 64 levels, shared parts copied once), so changing the caller's object afterwards no longer changes the attribute, the published value or the cluster a switchback served from it.
- Switchback experiments are now served as switchbacks. Earlier versions served a switchback that has a `unitType` as an ordinary experiment on that unit (a sticky variant that ignores clusters and periods), so units in running switchbacks move to their cluster's schedule, and their exposures move to the serving unit and one per period.
- The `X-Agent` header is now `absmartly-ruby-sdk/<version>` instead of `absmartly-ruby-sdk`, as the JavaScript SDK sends its versioned agent. Collectors and proxies that match the exact old value need updating.
- Every exposure in the publish payload now carries `ruleOverride` (`false` unless an assignment rule chose the variant), as the JavaScript SDK sends it. Consumers that compare the exact publish body (snapshots, proxies) see the extra field.
- Audience filters on `application` or `environment` now see the configured names (see Added), so a non-strict audience with such a condition stops flagging `audienceMismatch` on matching units, and a strict one stops serving them control.

### Fixed
- Every timestamp the SDK sends (`publishedAt`, `exposedAt`, `setAt`, `achievedAt`) is the current time in epoch milliseconds, as the Collector reads it and the JavaScript and Java SDKs send it. They used to be the context's creation time in seconds, so every event looked older than 50 years and stayed at one instant for the context's life. A `Time` passed to `Context.create` is still one fixed instant, now in milliseconds; a callable clock (`-> { millis }`) is read on each call. `publishedAt` is never earlier than an event in its batch, so a wall clock that steps back does not get the batch rejected.
- Nested `variants`, `applications` and `customFieldValues` in the context payload are read by key: an unknown key no longer fails the whole context and a reordered object no longer swaps fields (the bug dates back to v1.3.0). A missing key leaves that field `nil`.
- A `customFieldValues` entry with no `type` (or `type: null`) no longer makes `create_context` or `refresh` raise `NoMethodError`; its value is read as plain text and `custom_field_type` returns `nil` (the bug dates back to v1.3.0).
- `set_unit` stores the `to_s` text of any non-numeric UID (Symbols, `Rack::Session::SessionId`, UUID value objects), as in v1.3.0; `nil` or blank text raises "UID must not be blank."
- Integer unit UIDs are hashed from their exact decimal text, as in v1.3.0, so IDs beyond 2**53 keep distinct buckets.
- `Client#context_data` returns a new immutable `ContextDataResult` per call, so concurrent `create_context_async` calls and refreshes sharing a client can't read each other's in-flight state. The client's `data_future`, `exception` and `promise` readers still reflect the latest fetch.
- A raising event logger no longer breaks the operation that logs (initialization, treatment, publish).
- The SDK writes nothing to stderr, as in v1.3.0; failures are reported to the event logger as `error` events.
- `ABSmartly.new(config)` accepts a duck-typed config that responds to `to_hash` on Ruby 2.7.
- `in` with an object haystack finds symbol keys (audience attributes are parsed with symbolized names).
- An indeterminate audience result (no filter) keeps a cached assignment instead of re-assigning.
- An exposure or goal can no longer be queued after `close` sealed the context.

### Added
- Switchback experiments, served as the Collector and the Java SDK serve them (the R33 cluster-defined contract). An experiment with `randomizationType: "switchback"` lists in `switchbackClusters`, in order, the unit types it is linked to and the attribute path holding each one's cluster value (`/` nests, a quoted segment is a literal key, an integer segment indexes an array). The first linked unit, in declared order, whose attribute gives a value serves the experiment and its exposure; the value is the cluster key, used raw (never hashed): a non-empty String as is, an Integer as its decimal text, while a Float (`3.0` included), boolean, Hash, Array, `""` or `nil` gives none. The variant is the platform's balanced-block draw for the period `floor((now - switchbackStartAt) / switchbackPeriodMs)` and the experiment's 64-bit seed. No value, disagreeing units or a value outside `switchbackClusterValues` give control and no exposure; so do the time before `switchbackStartAt` and an unservable schedule (a start that is not hour aligned, a period of 0 or less, fewer than two arms), where rules, a strict audience and full-on still apply. Overrides, assignment rules (a split rule over the serving unit), strict audiences, full-on, traffic (on the serving unit) and custom assignments apply in the Collector's order; holdouts never apply to a switchback. One exposure is sent per experiment and period, stamped with the time that chose the period, and the cluster value is read once per period. Changing a unit's cluster attribute mid-period, before its exposure, is not supported: callers set it before the first read, and a change takes effect in the next period. The Collector resolves the serving unit and cluster again from the published units and attributes at `exposedAt`, so a switchback exposure that the batch would credit to another unit or cluster (an attribute changed within the period, a unit set afterwards, a write in the exposure's millisecond, a clock that stepped back) is published in a request of its own, with the units and attributes its period read and its own `exposedAt`; `publish` then sends more than one request. A string cluster value keys by its published UTF-8 text. The new experiment fields (`randomization_type`, `switchback_clusters`, `switchback_cluster_values`, `switchback_start_at`, `switchback_period_ms`, `switchback_carryover_duration_ms`, `switchback_burn_in_duration_ms`, `switchback_burn_out_duration_ms`, `switchback_design_type`, `switchback_estimand`) are optional; payloads without switchbacks assign as before and read no clock to do so.
- Assignment rules. An experiment's `assignmentRules` (a JSON string of `{"rules": [...]}`) are evaluated in order, and the first matching rule decides the variant, taking precedence over the audience and `audienceStrict`, traffic eligibility, full-on and custom assignments; only `set_override` beats a rule. An `assign` rule gives a fixed variant; a `split` rule (e.g. `"percentages": "20/30/50"`) hashes the unit with the experiment's own seed over its percentages, which must be non-negative and sum to 100 within 0.01. Rules can be scoped to `environments` (an empty list matches all) and their `conditions` are JSON expressions over the same attributes as audiences, including `application` and `environment`. Rule-assigned exposures carry `ruleOverride: true`, `assigned: false`, `eligible: true`, so the backend excludes them from analysis. A malformed rule is skipped in favour of the next one; an `assign` variant out of range or a split without one percentage per variant stops evaluation and falls back to normal assignment. While the unit is missing, a split rule gives the experiment's no-unit variant (the full-on variant, otherwise 0); once the unit is set, unexposed ones are re-resolved and exposed ones keep their variant. Invalid `assignmentRules` JSON is ignored for that experiment. A custom audience matcher that only implements `evaluate(audience, attributes)` keeps working: rules then run on the default rule engine.
- Holdouts, as in the JavaScript SDK. The context payload's `holdouts` list and each experiment's `holdoutIds` are read (`ContextData#holdouts`, `Experiment#holdout_ids` and `Experiment#holdout_type`, all optional). A unit held out by any holdout covering an experiment gets control for it (variant 0, `assigned: false`; control variable values are a fallback when no assigned, overridden or rule-won experiment supplies the key) and no exposure of its own, ahead of the audience, full-on, traffic and custom assignments; `set_override` and a matching assignment rule still win. Each covering holdout queues one ordinary exposure (the holdout's id and name, the experiment's unit type, its arm as the variant) per unit type, the first time a covered experiment is read with `treatment` or `variable_value`; like any exposure it is sent on `publish` or `close`. The arm is hashed with the covered experiment's unit and the holdout's own seeds; arm 0 holds the unit out and, in a three-arm holdout (a three-entry `split`), arm 1 holds out experiments that are not full-on. A covered experiment read with `treatment` or `variable_value` before its unit type is set gets no holdout arm; `set_unit` alone does not change that exposed assignment or expose the holdout for it (as in the JavaScript SDK); a later refresh that changes the experiment or its coverage can rebuild it. Unexposed assignments are re-resolved once the unit is set. Arms stay pinned while a holdout's iteration is unchanged, so a seed or split edit does not reassign or expose again. Holdouts without an id, with a split that is not a non-empty list of numbers or with non-integer seeds, and `holdoutIds` that name no holdout, are ignored (the JavaScript SDK may still assign or expose such malformed holdouts). Only integer IDs, integral floats and canonical decimal spellings are accepted; noncanonical text IDs are ignored, even when identical on both sides, and accepted text IDs publish as integers (unlike JavaScript on these malformed inputs). Payloads without holdouts assign and publish exactly as before.
- `semver_eq`, `semver_gt`, `semver_gte`, `semver_lt` and `semver_lte` operators for audience filters and rule conditions. A leading `v`/`V` and `+build` metadata are ignored, missing core parts count as `0`, and a release ranks above its pre-releases; an operand that is not a version gives `null`. A numeric operand is converted to text as the JavaScript SDK does (`toFixed(15)`, trailing zeros trimmed), so `1.0000000000000002` compares equal to `"1"`; other operators are unchanged.
- Audience filters now always evaluate `application` and `environment` (the application and environment names configured on the client), matching the JavaScript SDK. The SDK seeds the audience evaluation map with these system values first, then overlays user-set attributes, so a user attribute of the same name always wins, even when set after the context is created (it re-evaluates the cached assignment through `attrs_seq`). Empty or unset names are skipped, so a filter on `environment` with no environment configured leaves the key absent rather than matching `""`. Nothing new is published: the collector already attaches `application` and `environment` server-side, so the publish payload gains no `application`/`environment`/`app_version` attributes. `app_version` is never injected into the evaluation map. **This changes assignment for running experiments: a unit whose experiment has Audience enforced (`audienceStrict`) and an `environment`/`application` condition currently gets variant 0 (control) because the SDK never supplied those attributes; after upgrading, a unit that matches the audience is randomised normally, while a unit that does not match still gets control.**
- `Context#finalize`, which logs the `"finalize"` event (`EVENT_TYPE::FINALIZE`); `close` still logs `"close"` (`EVENT_TYPE::CLOSE`).
- `Context#variable_keys_list`, mapping each variable key to every experiment that defines it, in experiment id order; `variable_keys` still maps it to a single experiment name (see Breaking for which one).
- `retry_statuses` (on `ClientConfig` and `DefaultHttpClientConfig`) to opt in to retrying HTTP statuses, e.g. `[502, 503, 504]`. None are retried by default, as in v1.3.0.
- `retry_connection_failures` to opt in to retrying a refused connection on the context fetch (GET only). Off by default: with the default `max_retries` and backoff, a refused connection would block for about 15 s.
- `ABSmartly.new(endpoint, api_key:, application:, environment:, ...)` alongside `ABSmartly.new(config)`.
- Configurable connection pool settings: `pool_size` and `pool_idle_timeout`
